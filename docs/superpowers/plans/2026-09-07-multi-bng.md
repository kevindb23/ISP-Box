# Multi-BNG Connections Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Support multiple independent BNG connections throughout the NexusBox BNG module.

**Architecture:** Keep `bng_settings` as the per-device store, add ID-scoped repository/service/API operations, and retain an optional-ID default resolver for compatibility. The browser stores the selected BNG ID and sends it on all device-specific operations.

**Tech Stack:** PHP 8.1, PDO, existing router/controllers, vanilla module JavaScript, SQL migrations.

**Spec:** `docs/superpowers/specs/2026-09-07-multi-bng-design.md`

## Global Constraints

- Preserve existing BNG records during migration.
- Keep one application-wide `.env.secret-key`; never generate one key per BNG.
- Maintain old routes as backward-compatible defaults.
- Keep passwords encrypted and never return them to the browser.
